# 阶段 1 竖线：代码走读与测试手册

> 功能：页面上填车数、点「开始仿真」，后端用 SimPy 跑一个班次，返回 4 个指标。  
> 目标：打通「前端 → 后端 → 仿真内核 → 回写 → 前端展示」的完整链路。

---

## 一、先看这一张图：请求是怎么走的

```
浏览器 (localhost:5173)
  │  点击「开始仿真」
  ▼
App.vue  ──► useSimulationTask.run(config)          src/App.vue
  │           封装流程，页面里没有异步代码
  ▼
stores/task.ts  store.submit(config)                src/stores/task.ts
  │           调用接口，拿到 taskId 存进 Pinia
  ▼
api/simulations.ts → api/client.ts → fetch          src/api/
  │           POST /api/v1/simulations
  ▼
[vite 代理 /api → 127.0.0.1:8000]                   frontend/vite.config.ts
  ▼
api/v1/sim 做校验 + 转发，返回 202
  ▼
services/simulation_service.py  submit()            backend/app/services/
  │           建任务 PENDING→RUNNING，投递进程池
  ▼
ProcessPoolExecutor（子进程）
  │           run_scenario(config)
  ▼
simulation/engine.py  SimPy 循环                    backend/app/simulation/engine.py
  │           算出 kpi 字典并返回
  ▼
回到主进程：future 的回调 _on_finished()
  │           把 kpi 写回 TaskStore，状态 SUCCEEDED
  ▼
前端轮询 GET /api/v1/simulations/{id}
  │           status=SUCCEEDED → 取 kpi
  ▼
MetricCard × 4 显示产量 / 循环次数 / 利用率 / 平均等装
```

**两条容易看漏的关键线**：

1. 仿真在**子进程**跑，但结果要回到**主进程**的任务表——靠 `add_done_callback`；
2. 前端请求先打 5173（前端自己），由 vite 转发到 8000（后端），所以前端代码里只写 `/api/v1/...`，不写域名。

## 二、后端 6 个文件，各自在干什么

| 文件                                   | 一句话职责                   | 阅读重点                           |
| ------------------------------------ | ----------------------- | ------------------------------ |
| `app/main.py`                        | 创建 FastAPI 应用、注册路由      | 只有 `include_router`，没有业务代码     |
| `app/api/v1/simulations.py`          | 两个接口：`POST` 提交、`GET` 查询 | 注意 `status_code=202` 的含义       |
| `app/api/v1/__init__.py`             | 把路由统一挂到 `/api/v1` 前缀    | 将来加 v2 只需新增一个包                 |
| `app/schemas/simulation.py`          | Pydantic 模型（请求/响应结构）    | `extra="forbid"` 让拼错字段名直接报 422 |
| `app/services/simulation_service.py` | **核心**：提交任务、进程池、回调回写    | 见下方"三个关键点"                     |
| `app/simulation/engine.py`           | SimPy 仿真内核              | 见下方"三个语法点"                     |
| `app/db/task_store.py`               | 任务表（内存 dict + Lock）     | 封装成类，将来换 SQLite 只改这里           |

### engine.py 的三个 Python 语法点（不懂 Python 先看这里）

```python
yield env.timeout(t)          # ① 挂起 t 分钟，不是 sleep，不占 CPU，仿真时钟直接推进
with shovel.request() as req: # ② 向电铲申请工位；满了自动排队；with 退出自动释放
    yield req
rng = random.Random(seed)     # ③ 全局唯一随机实例，保证同 seed 结果一致
```

- ① 相当于 Java 里把任务挂到时间轮上，只是写法是生成器；
- ② 漏掉 `with` 会导致电铲被永久占死，其他车全部饿死；
- ③ 每台车各自 new 一个 Random，随机序列就乱了，可复现性立刻失效。

### service.py 的三个关键点

```python
_executor = None              # ① 惰性创建进程池（Windows spawn 会重复 import）
def _get_executor(): ...

future = _get_executor().submit(run_scenario, config)   # ② 传模块级函数，才能被 pickle
future.add_done_callback(lambda f, tid=task_id: _on_finished(tid, f))  # ③ 回调在主进程
```

- ① 模块导入时就建池 → 子进程里再建池 → `daemonic processes are not allowed to have children`；
- ② lambda / 内部类 / 对象方法都不能传给进程池；
- ③ **这是全项目最值钱的一行**：子进程的内存和主进程是隔离的，只有在主进程执行的回调里写 `TaskStore`，结果才查得到。

## 三、前端 8 个文件

| 文件                                 | 职责                                                     |
| ---------------------------------- | ------------------------------------------------------ |
| `main.ts`                          | 挂载 Vue + **Pinia**（必须先 `use(createPinia())` 再 `mount`） |
| `App.vue`                          | 页面：两个输入框 + 按钮 + 状态文字 + 4 张卡片                           |
| `composables/useSimulationTask.ts` | 编排"提交 → 轮询 → 取结果"，页面只调 `run()`                         |
| `stores/task.ts`                   | Pinia：taskId / status / kpi / error，含轮询逻辑              |
| `api/client.ts`                    | fetch 封装：统一 baseURL 与错误处理（422 的 detail 是数组，要特殊处理）      |
| `api/simulations.ts`               | 两个接口函数，页面不直接碰 fetch                                    |
| `types/simulation.ts`              | 与后端 Pydantic 字段一一对应                                    |
| `components/MetricCard.vue`        | 纯展示卡片，无业务逻辑                                            |
| `utils/format.ts`                  | 吨位千分位、小数转百分比                                           |

分层原则：**页面不放异步逻辑，组件不放业务判断**，所以 `App.vue` 只有 20 行脚本。

## 四、怎么测试

### 1）后端内核（不启动服务）

```powershell
cd D:\Code\mine-simulation\backend
.\.venv\Scripts\python.exe -m app.simulation.engine
```

预期：打印车数扫描表，**产量边际递减、等装时间递增、利用率递减**，最后一行 `一致: True`。

### 2）后端自动化测试（8 个用例）

```powershell
.\.venv\Scripts\python.exe -m pytest
```

预期 `8 passed`。其中 `test_service.py` 验证的是**异步回写真的生效**，这是最容易写错的地方。

### 3）启动服务 + 手工打接口

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload --port 8000
```

浏览器打开 <http://127.0.0.1:8000/docs> 可以直接点。用 curl（PowerShell 里请用 `curl.exe`）：

```bash
# 提交（应返回 202 + task_id）
curl.exe -X POST http://127.0.0.1:8000/api/v1/simulations `
  -H "Content-Type: application/json" -d '{"trucks":4,"shift_minutes":120,"seed":42}'

# 查询结果（把 id 换成上一步返回的）
curl.exe http://127.0.0.1:8000/api/v1/simulations/<task_id>

# 参数校验：trucks=999 或字段名拼错 → 422
# 查不存在的任务 → 404
```

### 4）前端联调

```powershell
cd D:\Code\mine-simulation\frontend
npm run dev
```

打开 **<http://localhost:5173>**（注意是 `localhost`，不是 `127.0.0.1`——Vite 默认只监听 IPv6 回环地址）。

点「开始仿真」，3 秒内应出现 4 张卡片。改车数再点，观察产量上升但等装时间也上升。

### 5）类型检查与构建

```powershell
npm run build     # vue-tsc 类型检查 + vite 构建，通过才算没写错
```

## 六、Python 语法速查（给 Java 开发）

| Python                       | Java 对照                           |
| ---------------------------- | --------------------------------- |
| `def f(x: int) -> dict:`     | 类型注解只是提示，运行时不强制（Pydantic 才会校验）    |
| `dict \| None`               | `Map or null`，Python 3.10+ 写法     |
| `**fields`                   | 可变参数，类似 `Map<String,Object> args` |
| `with lock:`                 | `synchronized(lock){}`，退出自动释放     |
| `lambda x: x+1`              | `x -> x+1`                        |
| `f"{a:.2f}"`                 | `String.format("%.2f", a)`        |
| `if __name__ == "__main__":` | `public static void main`         |
| `global _executor`           | 声明要改模块级变量（Java 没有这个限制）            |

## 七、出问题先查这里

| 现象                                                    | 原因                                             |
| ----------------------------------------------------- | ---------------------------------------------- |
| `daemonic processes are not allowed to have children` | 进程池在模块导入时创建了；必须惰性创建                            |
| `PicklingError`                                       | 传给进程池的不是模块级函数                                  |
| 任务一直是 RUNNING                                         | 回调没触发或被吞异常，看 `error_message` 字段                |
| 前端 404 / 502                                          | 后端没起，或 vite 代理目标端口不对                           |
| `127.0.0.1:5173` 打不开                                  | Vite 默认监听 `localhost`（IPv6），用 `localhost:5173` |
| 改了后端但前端类型没更新                                          | 类型目前是手写的 `types/simulation.ts`，两边要同步（后续可自动生成）  |
